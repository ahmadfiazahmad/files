# VerifyAbroad-AI — FastAPI Backend

A study-abroad fraud-verification assistant for Pakistani students. This
backend was reviewed, debugged, and completed from a working MVP — see
`CHANGES.md` for the full audit findings and what was fixed.

## Locked pipeline

```text
Student chat (multi-turn counter-questioning, one field at a time)
  ↓
Structured case JSON
  ↓
Evidence upload (image / PDF / text)
  ↓
Gemini multimodal extraction → structured claims
  ↓
Parallel verification
  ├─ Institution: Hipo + HEC static + Tavily + Gemini Google Search
  ├─ Agent: OpenSanctions + Tavily + Gemini Google Search + banned dataset + RAG
  └─ Payment: Python rules + Tavily + Gemini Google Search + RAG
  ↓
Document cross-check + temporal logic
  ↓
Evidence normalization (fault-tolerant: one bad source degrades to
unable_to_verify instead of failing the whole run)
  ↓
Authority-weighted aggregation → domain statuses
  ↓
Deterministic risk engine (pure Python, no AI)
  ↓
Final report: LLM writes fraud_signals/recommendation/safer_action only;
every domain's status/summary/evidence list is assembled in Python from
the aggregator's output, never re-generated by the LLM.
  ↓
Final report + WHED/SECP manual-check links + draft display-status/emoji
```

Tavily and Gemini Google Search run **in parallel as two independent
sources**, each producing its own evidence record (not a fallback chain) —
confirmed against the original implementation and preserved as-is.

## Providers

- **Gemini** — primary LLM, structured JSON, multimodal document/image
  extraction, embeddings, final analysis, and Google Search grounding.
  Default model `gemini-3.8-flash` (verified current as of Sept 2026).
- **Groq** — fallback LLM, `qwen/qwen3.8-27b` (verified current).
- **Tavily** — primary controlled live-web research.
- **OpenSanctions** — agent/company screening.
- **Hipo** — university identity lookup (free, keyless).

Model names rotate; if you see extraction/JSON errors that look like a
"model not found" response, check https://ai.google.dev/gemini-api/docs/models
and https://console.groq.com/docs/models and update `GEMINI_MODEL` /
`GROQ_MODEL` in `.env`.

## Requirements

Python 3.11+

Install:

```bash
python -m venv .venv && source .venv/bin/activate   # or .venv\Scripts\activate on Windows
pip install -r requirements.txt
```

For running the test suite, install dev dependencies instead:

```bash
pip install -r requirements-dev.txt
```

> **Note on this review:** dependency resolution and live API calls could
> not be executed in the sandbox this review was done in (no outbound
> network access). Requirements were checked for known conflicts via
> documentation research (supabase-py 2.31.0 uses pydantic 2.11.x / httpx
> 0.28.1, both inside this project's existing pins — no conflict found),
> but you should run `pip install -r requirements.txt` in a clean venv
> yourself before deploying, and report back if anything fails to resolve.

## Database setup

**Dev (SQLite):** tables are auto-created on startup when
`ENVIRONMENT=development` (or `dev`/`local`/`test`). No extra step needed.

**Production (Postgres/Supabase), or any time you want real migrations:**

```bash
# First time: applies the initial schema (alembic/versions/0001_initial_schema.py)
alembic upgrade head
```

That initial migration was hand-written to match `database/models.py`
exactly (the repository had no migrations checked in at all). Verify it
against a real database with `alembic check` before depending on it in
production, and generate future migrations the normal way:

```bash
alembic revision --autogenerate -m "describe your change"
alembic upgrade head
```

## Known genuine gaps — still need your input

1. **`data/hec_recognized.json` and `data/banned_agents.json` are still
   empty placeholders** (`"institutions": []` / `"agents": []`). This was
   confirmed, not changed — the loader (`data/loader.py`) correctly handles
   an empty list without crashing, but until you supply real HEC/FIA-sourced
   entries, the static-dataset checks in those domains will never
   contribute a `verified`/`contradicted` result on their own (live web
   research and the other sources still run normally).
2. **Draft display-status/emoji mapping** (`risk/display_status.py`) — the
   product brief names two status schemes that don't map 1:1 (per-domain
   VERIFIED/UNVERIFIED/CONTRADICTED/SUSPICIOUS/UNABLE_TO_VERIFY vs. the
   student-facing 🟢/🟡/🟠/🔴/⚪ scheme with different label names). I wrote
   one reasonable interpretation and flagged it clearly in code/response —
   please confirm the intended semantics before the frontend relies on it.
3. **Supabase Storage / pgvector / Postgres paths are unexercised** — the
   `storage.py` and `rag/retriever.py` interfaces are written for the
   config-only swap as designed, but only the local-filesystem/SQLite path
   was ever actually exercised (no network access to Supabase in this
   review). Test the prod paths before relying on them.
4. **Requirements.txt was not `pip install`-verified end-to-end** — see the
   note above.
